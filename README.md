# CALLING

![CALLING项目概念封面](docs/assets/cover.jpg)

把脑子里乱糟糟的话先记下来，再慢慢分清：哪些是要对外完成的事情，哪些是向内生长的念头。CALLING 是我的第一款 vibe coding 产品，最初的 demo 用 Manus 做出，也是一个我自己会用的记录工具。

**第一次来：** 先看 [用户说明书](CALLING_用户说明书.md)，再看下面的创作过程。完整应用需要后端、数据库及 AI 服务；当前仓库没有已验证的公开完整体验地址，不需要为看作品先注册账户。

## 它想解决什么

意识流记录常常把待办、想读的书、情绪和突然冒出的想法混在一起。我想保留“先说出来”的轻松感，再用分类、日历和日记，把记录接回生活。界面分为日历、日记、首页、世界和内心：向外处理责任，向内照顾自己的成长。

## 我怎么走到这里

做自己的 TODO，好像是很多人开始 vibe coding 的第一站，我也没有例外。那时我希望做一个更适合自己的工具，帮自己整理生活。真正用起来后，我开始意识到：工具能承接混乱，却不能替我决定什么重要；对我有用，也不等于已经找到了所有人的需求。

所以我没有只把它当作一个“AI 自动列清单”的功能练习。我更在意记录时会不会被打断，任务和愿望要不要放在一起，以及完成外部责任与照顾内在状态能否同时存在。这也是 CALLING 想保留一点禅意的原因。

## 做的过程中遇到的问题

- **一句话常常不止一种意图。** 自动分类方便，但分类结果仍可能需要人修正。现有说明书里也保留了快捷记录暂不支持手动重新分类等限制。
- **看得见的界面与完整可用的产品之间还有距离。** 登录、持久化和 AI 调用需要后端配合，不能把静态页面当成完整应用。
- **游客体验与真实保存要分清。** 游客模式并不等于拥有全部账户功能，不能承诺记录已经可靠地同步到云端。

这次尝试让我开始从“把功能做出来”转向“自己能不能持续用、哪里会失望”。它仍然是持续打磨中的个人产品。
